# ToDo — Secret Santa (бесплатный сервис без тарифов)

> Принцип проекта: **все возможности доступны всем бесплатно**. Нет страницы Premium, нет тарифов, нет оплаты, нет подписок, нет пробных периодов и даты окончания доступа.
> Источник идей для функций: описание расширенных возможностей santa-secret.ru и раздел FAQ (просмотрено 25.11.2026). Коммерческая модель исходного сайта не переносится.

## 0. Текущее состояние репозитория

- [x] Express 5 + Vue 3 + Vite 7 + Tailwind 4; `npm run dev` / `npm run build` работают.
- [x] Есть `/api/health`, `/api/message`, раздача `dist` в production, прокси `/api` в dev.
- [x] Нет базы данных, сессий, реальных игр, жеребьёвки и деплоя; чат не входит в первую очередь.
- [x] Есть дизайн-прототип: лендинг, темы, демо кабинета; полноценного роутинга и бэкенда пока нет.

## 0.1 Дизайн-прототип (готов)

- [x] Лендинг по мотивам santa-secret.ru: hero, выбор темы, шаги, возможности, нижний CTA и футер.
- [x] Переключатель тем и режимов ночь/день на демо-данных.
- [x] Все 10 тем из исходного сайта добавлены в прототип; карточки показывают ночной и дневной вариант.
- [x] Демо кабинета организатора: прогресс, участники, ручное назначение пар и фильтр истории.
- [x] Адаптивная шапка с доступным мобильным меню, видимый фокус, reduced-motion, токены и шрифты; кнопка «Войти» заменена на «Открыть демо».
- [x] Подключены `.opencode/skills` и скилл `commit-and-todo` с правилами «коммит + ToDo»; `opencode.json` использует массив `skills`.

## 0.2 Фундамент API (готов)

- [x] Модуль SQLite открывает БД по `DB_PATH`, включает WAL и внешние ключи, создаёт схему и загружает 10 тем из данных прототипа.
- [x] REST `/api/games`: создание, список, карточка игры, участники, исключения, жеребьёвка, ручное назначение пар, раскрытие пары и история событий.
- [x] Жеребьёвка строит круговые пары, учитывает исключения и сохраняет ручные назначения.
- [x] `.env.example` и игнорирование локального каталога `data/`.

## 1. Продуктовые решения

- [x] 1.1 Зафиксировать: весь функционал бесплатный, без аккаунта и без обязательного email.
- [x] 1.2 Не создавать страницу тарифа, кнопки покупки, чек-out, личный кабинет биллинга и любые напоминания о продлении.
- [x] 1.3 Не вводить лимиты «бесплатно/платно»: 10 вопросов, 3 организатора и рассылка доступны сразу.
- [x] 1.4 Не показывать рекламу: рекламных блоков в проекте нет.
- [x] 1.5 Использовать страницу с описанием возможностей исходного сайта только как список идей, не как тарифную сетку.
- [ ] 1.6 Метрики успеха: созданная игра → приглашённые участники → проведённая жеребьёвка → отправленный подарок → возврат организатора.
- [x] 1.7 Чат — самый низкий приоритет: базовый сценарий работает без него, реализуется последним.
- [x] 1.8 База данных на текущем этапе — SQLite; решение пересматриваем позже, без преждевременного перехода на серверную БД.
